Topic 01 · Hardware Assembly
Desktop PC Assembly — Motherboard & RAM Installation
A complete walkthrough of assembling a desktop PC from bare components, covering form factors, socket standards, slot installation procedures, power delivery, and POST verification.
Tools & Safety Preparations
Required Tools
  • Phillips-head screwdriver (PH2) — primary tool for most screws
  • Anti-static wrist strap — connect to unpainted metal on case
  • Thermal paste — pre-applied on most coolers, otherwise apply separately
  • Magnetic tray — holds screws, prevents losing tiny hardware
  • Cable ties / velcro straps — for cable management
  • Flashlight — for dark case interiors
  • Isopropyl alcohol (90%+) — clean old thermal paste
ESD & Workspace Safety
  • Work on a hard, non-carpeted surface (wood table, not carpet)
  • Anti-static wrist strap grounds you to prevent ESD discharge
  • If no strap: touch unpainted metal chassis frequently to discharge
  • Keep components in anti-static bags until needed
  • Never touch gold contacts on PCIe cards, RAM sticks, or CPU pins
  • Power off and unplug PSU before working (but leave PSU grounded)

Step-by-Step Assembly Procedure
  1. 1
    Prepare the case: Remove side panels. Lay case flat on its side. Identify the rear I/O cutout. Remove the pre-installed I/O shield (punch out). Note the motherboard standoff positions corresponding to your form factor.
  2. 2
    Install brass standoffs: Screw brass standoffs into the case threaded holes matching your motherboard's mounting pattern. These lift the board off the case pan to prevent electrical shorts. Missing a standoff causes board flex; extra standoffs cause shorts.
  3. 3
    Install the custom I/O shield: Press the motherboard's I/O shield into the case cutout from inside until all edges click into the frame. Align tabs — they will contact board connectors for grounding.
  4. 4
    CPU installation: For Intel LGA: lift the socket retention arm, place CPU with golden triangle aligned to socket triangle, lower arm. For AMD AM5/LGA: same procedure — CPU drops in with no force. For older AMD AM4/AM3: PGA socket — align CPU pins with socket holes, lever closes. Never use force on any CPU socket.
  5. 5
    RAM installation: Open DIMM slot retention clips on both ends. Locate the notch on the RAM stick — this is a key that ensures correct orientation. Align the notch to the slot key. Press down firmly and evenly with both thumbs until both retention clips snap closed. You should hear and feel a distinct click. For dual-channel operation, populate slots A2 + B2 (second and fourth from CPU) unless the manual specifies otherwise.
  6. 6
    M.2 NVMe SSD (on-board): Remove the M.2 heatsink if present. Insert M.2 drive at 30° angle into the M.2 slot (keyed connector). Press flat and secure with the small retaining screw. Replace heatsink.
  7. 7
    Mount the motherboard: Lower the board into the case, aligning rear I/O ports with the shield cutouts. Confirm all standoffs align with the mounting holes. Insert all mounting screws finger-tight first, then use a star/cross pattern to torque evenly — prevents board warping.
  8. 8
    Install CPU cooler: Apply thermal paste if not pre-applied (pea-sized dot on CPU IHS center). Mount cooler backplate (if required), then secure cooler. For tower coolers: use screws or push-pins. Tighten in diagonal pairs for even IHS contact pressure.
  9. 9
    Connect PSU cables: (1) 24-pin ATX main power to motherboard. (2) 4+4 pin CPU EPS power to top-left corner of board (separate from 24-pin, often overlooked). (3) PCIe power cables to GPU when installed.
  10. 10
    Connect SATA storage: L-shaped SATA data cable from motherboard SATA port to drive. SATA power from PSU to drive. Note: SATA data is separate from power, unlike older IDE.
  11. 11
    Connect front panel headers: These are small 1- or 2-pin connectors. Connect to F_PANEL header on board. Key connections: PWR_SW (power button), RESET_SW, HDD_LED (+/−), PWR_LED (+/−), HD_AUDIO, USB 2.0 header, USB 3.0 header. Check manual for polarity — LEDs are direction-sensitive (wrong polarity = LED won't light, but won't damage hardware).
  12. 12
    Connect fans: CPU fan to CPU_FAN header (mandatory — if unconnected, BIOS will halt boot). Case fans to SYS_FAN or CHA_FAN headers. Pump for AIO to AIO_PUMP or CPU_OPT.
  13. 13
    Cable management: Route all cables behind the motherboard tray through rubber-lined cutouts. Use velcro ties. This improves airflow and allows the side panel to close without pinching cables.
  14. 14
    First boot / POST: Connect monitor, keyboard, power. Power on. System should POST (Power-On Self-Test), display BIOS screen. If RAM is new, enable XMP/EXPO profile in BIOS (AI Overclocking on ASUS, DOCP on some ASUS, EXPO on AMD platforms) to run RAM at rated speed rather than JEDEC default (2133 MHz).

Topic 02 · Hardware Disassembly
Laptop Keyboard & Storage Unit Disassembly
Detailed procedure for safely removing a laptop keyboard and storage drives (HDD, SATA SSD, M.2 NVMe), including connector types, ribbon cable handling, and reassembly notes.
Pre-Disassembly Checklist
Safety Steps (Always Do First)
  • Power off completely (not sleep/hibernate)
  • Disconnect AC adapter
  • Discharge residual energy: hold power button 5 seconds after unplugging
  • Work on anti-static mat; wear wrist strap
  • Photograph the underside screw locations before removal
  • Use a magnetic parts tray or tape screws to labeled paper
Required Tools
  • JIS screwdrivers — many Japanese laptops use JIS #0 and #1 (not Phillips, though PH looks similar)
  • Torx T5/T4 — used on some ultrabooks (Apple, Surface)
  • Plastic pry tools / spudgers — never metal on chassis
  • Tweezers — for ribbon connectors
  • Opening picks — thin guitar-pick shape for clip panel release
  • iFixit / repair guide for exact model
Keyboard Disassembly — Base Panel Method
  1. 1
    Remove base screws: Flip laptop upside-down. Remove all underside screws. Note: screws often differ in length (shorter at front edges, longer near hinges). Document positions. Some screws hide under rubber feet (peel them back) or warranty stickers (breaking = voiding warranty).
  2. 2
    Release base panel clips: The base panel is held by friction clips around its perimeter in addition to screws. Insert a plastic opening pick into the seam between base and top shell. Slide around perimeter to release clips sequentially. Listen for clicking sounds as clips release — do not force.
  3. 3
    Open the base panel: Start lifting from a corner (usually near hinges where there are fewer clips). Swing open gently — watch for cables that may be routed to the base panel (battery cable, fingerprint sensor cable, speaker cables).
  4. 4
    Disconnect the battery first: Before touching anything else, find the battery connector on the motherboard and disconnect it. This is a flat multi-wire connector, usually secured by a small latch or gentle friction. Disconnecting eliminates risk of short circuits.
  5. 5
    Access keyboard cable: The keyboard connects to the motherboard via a ZIF (Zero Insertion Force) ribbon cable. Locate the ribbon cable connector on the motherboard. Flip the brown/tan/black plastic latch upward (90° — it's a hinge, not removable). The ribbon cable then slides out freely — zero force required. Never pull the cable directly.
  6. 6
    Remove keyboard screws (if any): Some designs have 2–4 small screws holding the keyboard plate to the top chassis. Remove these. Other designs use only clips along the top or bottom edge of the keyboard bezel.
  7. 7
    Release keyboard clips: On designs where keyboard installs from the top, insert a thin plastic tool along the keyboard bezel edges to release the retention clips. Push inward, not upward, to disengage.
  8. 8
    Lift keyboard out: Tilt keyboard up carefully. There is often a second, shorter ribbon cable (backlight or trackpad). Disconnect this via its own ZIF latch before fully removing the keyboard.
ZIF Connector Types — Critical Detail
Top-Lock ZIF
  • Latch flips upward (toward you) like a hinged lid
  • Latch is part of the connector housing — don't remove it
  • Cable slides in/out horizontally with zero force once latch is open
  • Most common type in modern laptops
  • Close latch firmly after inserting cable — press until it's flat
Bottom-Lock / Slide-Lock ZIF
  • Latch slides outward (parallel to board surface) to release
  • Less common but found in some older/slim designs
  • Do not try to pry upward — you will break the connector
  • Use tweezers to slide latch out; slide cable in/out
  • Lock by sliding the latch back until it clicks
Storage Unit Disassembly
2.5" SATA HDD / SSD Removal
  1. 1
    After base panel is open, locate the 2.5" drive bay. Drive is usually secured by a caddy with 2–4 side screws or a rubber bumper system.
  2. 2
    Disconnect the SATA connector: In most laptops, a single L-shaped SATA combo connector carries both data and power. Pull straight out (parallel to the board surface) from the drive end.
  3. 3
    Some designs use a ribbon-cable SATA adapter (interposer board) — disconnect the ribbon, then remove the drive from its caddy.
  4. 4
    Remove the 4 caddy screws (usually M3×3mm). Slide drive out of caddy. Transfer caddy to new drive before reinstalling.
M.2 NVMe / M.2 SATA SSD Removal
  1. 1
    Locate M.2 slot — usually under a thermal pad/heatsink or shield. Remove heatsink screws and thermal pad if present.
  2. 2
    Remove the single small screw at the far end of the M.2 drive (M2×3mm). Hold the drive as you do this — it will spring up to ~30° when the screw is removed.
  3. 3
    Slide the drive straight out at the ~30° angle from the M.2 edge connector. The connector is at one end; the screw hole is at the other.
  4. 4
    To install new drive: insert at 30°, align connector notch with slot key (M-key for NVMe, B+M-key for SATA), press gently until seated, press flat and secure screw. Apply new thermal pad if removing old one.

GPU Installation — Step by Step
  1. 1
    Case preparation: Remove PCIe slot covers from the case rear panel. For a 2-slot GPU, remove covers at positions 1 and 2. Use a flat-head screwdriver or unscrew them. Keep unused covers in place to maintain airflow.
  2. 2
    Unlock the PCIe x16 slot: The primary PCIe x16 slot (closest to the CPU) has a retention latch at its far end. Push it away from the slot (outward) to unlock it. This prevents accidental removal during transport once the card is installed.
  3. 3
    Align the GPU: Hold the GPU by its heatsink shroud and PCB edges. Align the gold-finger PCIe connector with the x16 slot. Align the bracket cutouts with the rear case slots. The GPU should hover directly above the slot before pressing down.
  4. 4
    Seat the GPU: Press down firmly and evenly across the full PCIe connector length until you hear/feel the retention latch click into place. Verify the latch is engaged — if not, the GPU may appear seated but have a loose electrical connection.
  5. 5
    Secure the bracket: Screw the GPU's metal bracket to the case with 2–3 screws (same location as the slot covers you removed). This provides mechanical support and prevents the heavy GPU from sagging the PCIe slot over time.
  6. 6
    GPU support bracket (optional but recommended): Very heavy GPUs (RTX 4090, RX 7900 XTX) can cause PCIe slot sag over months. A GPU support bracket (third-party accessory) props up the GPU at the non-bracket end.
  7. 7
    Connect PCIe power: Modern GPUs require one or more power cables from the PSU. Connect 8-pin, 6-pin, or 16-pin (12VHPWR) connectors. Never daisy-chain: do not use a single PSU cable with two 8-pin connectors for a GPU requiring two separate 8-pin connectors. Use separate cables from the PSU for each connector when possible.
  8. 8
    12VHPWR adapter warning: Some adapters (3× 8-pin to 16-pin) have had melting issues. If your GPU ships with this adapter, ensure correct connection — all pins fully seated, no tension on the cable at the connector. NVIDIA updated to a sturdier 16-pin native cable in RTX 4080/4090 FE revision.

Thermal Management in Gaming PCs
Air Cooling Airflow Design
  • Positive pressure: more intake fans than exhaust — slightly reduces dust ingress
  • Negative pressure: more exhaust — keeps GPU/CPU cooler but sucks in more dust
  • Recommended layout: front intake + top/rear exhaust. GPU exhausts hot air out rear panel.
  • Fan orientations: front/bottom fans point inward (intake); rear/top fans point outward (exhaust)
  • GPU blower cooler: better for tight cases (exhausts directly out back); open-air coolers: better for cases with good airflow
AIO Liquid Cooler Installation
  • Mount radiator at front or top case position
  • Front radiator: intake fans pull cool air from outside through rad (best for CPU temps)
  • Top radiator: exhaust — pulls air from inside case; slightly worse CPU temps but keeps VRMs cooler
  • Pump connects to CPU_OPT or AIO_PUMP header on motherboard (full speed, no PWM throttling)
  • Check case clearance — 360mm rad requires 3 × 120mm fan mounts

Exam Key Points GPU installs in PCIe x16 slot (closest to CPU). The retention latch must click. Never use a single daisy-chained PSU cable for dual 8-pin GPU power — use two separate cables. Above 4G Decoding must be enabled for large VRAM GPUs. Resizable BAR / SAM requires both CPU and GPU support plus BIOS/driver enablement.

Pre-Disassembly Precautions
Electrical Safety
  • Fully discharge battery before starting — run it down to 0% or disconnect the built-in battery first thing after opening base panel
  • Anti-static wrist strap required — connect to a known ground (metal table leg, wall outlet ground)
  • Anti-static mat preferred over any fabric surface
  • Even with battery disconnected, capacitors retain charge briefly — wait 10–15 seconds after disconnecting before touching board
  • Never work near synthetic fabrics, carpet, or in low-humidity environments without grounding
Documentation & Organization
  • Photograph every step before removing anything — cable routing, connector positions, screw locations
  • Screw matrix: tape screws to a paper diagram of the board showing where each came from
  • Label or sketch cable connector positions — many look identical but go to specific headers
  • Download service manual for the exact model (manufacturer support pages, iFixit, Notebookcheck teardown)
  • Note cable routing paths — cables pinched or misrouted on reassembly cause overheating or connectivity issues

Motherboard Removal Sequence
  1. 1
    Remove all peripherals first: Battery (disconnect + unscrew), SSD, WWAN card, RAM (if not soldered), optical drive if present. Lighten the board before removing it.
  2. 2
    Remove heatsink / cooling assembly: The heatsink often spans CPU and GPU die. Remove screws in reverse-numbered order (from highest to 1) to release pressure evenly. Twist gently to break thermal paste bond — never yank straight up.
  3. 3
    Disconnect all board connectors: Battery cable first, then: display cable, webcam cable, keyboard ribbon, trackpad ribbon, power button cable, speaker cables, antenna cables, USB board cables, fingerprint sensor cable. Each one must be labeled or photographed.
  4. 4
    Remove board-to-chassis screws: These are often hidden under stickers, foam pads, or rubber gaskets. Check every corner and center of the board. Missed screws = cracked PCB when lifting.
  5. 5
    Check for port anchors: USB, HDMI, SD card, and audio jacks are often soldered to the board and protrude through chassis cutouts. The board must slide at a specific angle to clear these. Never pry straight up.
  6. 6
    Lift board at correct angle: Usually tilt hinge-side up first, then slide toward the hinge end to clear port cutouts. Support the board evenly with both hands.
  7. 7
    Place on anti-static mat: Never place the bare motherboard directly on a metal surface or bare table. Component-side up unless servicing the underside.
BGA vs LGA — Critical Distinction for Laptops
BGA (Ball Grid Array) — Laptop CPUs
  • CPU is soldered directly to motherboard during manufacturing
  • Solder balls form electrical connections beneath the chip
  • Cannot be replaced by end user — requires professional reballing equipment
  • All modern laptop CPUs: Intel Core Ultra, AMD Ryzen Mobile are BGA
  • Failure = entire motherboard replacement
LGA (Land Grid Array) — Desktop CPUs
  • CPU is socketed — removable and replaceable
  • Pins are on the socket (motherboard side for Intel, CPU side for AMD AM4/AM5 historically)
  • AMD AM5 is LGA (pins on socket); Intel LGA 1851 also on socket
  • Drop-in CPU upgrade possible without board replacement
  • Bent socket pins can be straightened carefully with a pin or mechanical pencil
Irreversible Damage Risks Torn ZIF connector from board = PCB-level repair needed (extremely expensive). Bent or broken antenna cable center conductor = WiFi failure. Cracked PCB trace from board flex = subtle intermittent faults. Wrong-length screw into a short standoff hole = cracks the PCB from below.
Exam Key Points Laptop CPUs are BGA (soldered) — not user-replaceable. ZIF connectors require latch opening before cable removal. Disconnecting the battery is the first step after opening the base panel. Screw-size documentation and photographic record-keeping are essential precautions. Reverse-numbered heatsink screw removal order prevents die cracking.

ECC RAM — Why It Matters in Workstations
Error Correcting Code Memory
  • DRAM bit flips: Cosmic rays and thermal noise can randomly flip bits in DRAM. At scale (TBs of RAM), this happens multiple times per day.
  • ECC detects and corrects: ECC RAM adds extra bits (single-bit error correction, double-bit error detection — SECDED) to each memory word. Hardware corrects single-bit errors silently.
  • UDIMM ECC: Unbuffered ECC — similar to consumer RAM but with error correction. Supported by some workstation/server Xeons and AMD Ryzen Pro.
  • RDIMM (Registered): Register buffer chip between controller and DRAM chips. Reduces electrical load, enables more DIMMs per channel. Required for 4+ DIMMs per channel.
  • LRDIMM (Load-Reduced): Further isolates memory bus using iMB buffer. Enables the highest DIMM counts (8+ DIMMs per channel) and maximum capacity.
  • Cannot mix ECC and non-ECC in same system — will not boot or will disable ECC.
Workstation Assembly Procedure
  1. 1
    Case selection and preparation: Full-tower or rack-mount chassis. Ensure clearance for large CPU heatsinks (workstation CPUs have higher TDPs). Install case in final position before heavy components — a fully built workstation can exceed 40kg.
  2. 2
    Motherboard installation: Workstation boards may use 12-pin or proprietary power connectors. Check manual. Install standoffs matching board layout. Some workstation boards have a daughterboard for power distribution.
  3. 3
    CPU installation: Workstation CPUs are large and heavy. Intel LGA 4677: use the socket loading arm, place CPU in carrier frame, lower into socket using the rail mechanism. AMD TRX50: similar rail system. Never remove CPU from its carrier frame before installation.
  4. 4
    ECC RAM installation: Populate channels symmetrically. Workstation boards have 8–16 DIMM slots. Fill in the order specified in the manual (often pairs per channel: A1+B1, C1+D1, etc.) for maximum bandwidth.
  5. 5
    Professional GPU installation: Professional GPUs are often single-slot blower designs. Install in PCIe x16 slot. Professional GPUs may require specific driver installation before use — do not use gaming drivers.
  6. 6
    Storage — RAID configuration: Install NVMe/SAS/SATA drives in hot-swap bays if equipped. Configure RAID through BIOS RAID utility or OS software RAID. Common workstation configs: RAID 1 (mirrored, for OS reliability), RAID 5/6 (parity for data drives).
  7. 7
    Expansion cards: Install in PCIe slots: RAID controller (HBA), 10 GbE NIC, SATA expansion card, video capture, etc. Fill slots from top down; use risers if needed for clearance.
  8. 8
    Power — high-wattage PSU: Workstations may use 1200–2000W PSUs. Modular PSUs recommended — use only the cables you need. Some workstation PSUs use proprietary connectors (Dell, HP).
Exam Key Points ECC RAM = Error Correcting Code; corrects single-bit errors silently — critical for workstations running 24/7 on large datasets. RDIMM vs UDIMM: RDIMM has a register buffer reducing bus load. Workstation GPUs have ISV-certified drivers for professional CAD/3D software. Threadripper Pro and Xeon W have up to 128 PCIe lanes — far more than consumer platforms (24–48 lanes).
Topic 06 · Hardware Disassembly
Laptop Cooling Fan & Processor Disassembly
Detailed procedure for accessing and replacing laptop cooling fans, removing the heatsink, re-applying thermal compound, and understanding laptop thermal architecture including heat pipes and vapor chambers.
Laptop Thermal Architecture
Heat Pipe Cooling (Traditional)
  • Copper heat pipes run from CPU/GPU thermal pads to fan-mounted radiator fins
  • Heat pipe interior contains working fluid (usually water or acetone) in a partial vacuum
  • Fluid evaporates at hot end (CPU die), travels as vapor to cold end (fins), condenses, wicks back via capillary action
  • Passive — no moving parts; extremely reliable
  • Multiple heat pipes in parallel increase capacity (2–5 pipes in gaming laptops)
Vapor Chamber (Premium Design)
  • Flat sealed chamber filled with working fluid
  • Spreads heat in 2D (vs 1D for heat pipes), better for large CPU/GPU die packages
  • Found in premium gaming laptops (ASUS ROG, Razer Blade, MSI Titan)
  • Lower thermal resistance than equivalent heat pipe arrays
  • Cannot be repaired if punctured — replace entire heatsink assembly
Cooling Fan Disassembly
  1. 1
    Open the base panel: Remove all base screws. Use plastic pry tool to release clip around perimeter. Note: some gaming laptops have additional screws hidden beneath the hinge area — pry only after all screws removed.
  2. 2
    Disconnect battery: Always the first connector to disconnect after opening. Pull battery connector by housing parallel to board surface.
  3. 3
    Locate fan connectors: One or two fan connectors on the motherboard — small 3-pin or 4-pin connectors next to each fan. They are friction-locked. Grip the connector housing (plastic part) with tweezers or fingers; do not pull the wire bundle.
  4. 4
    Remove fan screws: Each fan has 2–4 small screws mounting it to the chassis or heatsink frame. These are usually M2×3mm. Remove them — the fan may still be attached to the heatsink assembly.
  5. 5
    Fan + heatsink as one unit: In most designs, the fan and heatsink are a single replaceable assembly. Removing the heatsink screws also releases the fan. Proceed to heatsink removal steps below.
  6. 6
    Stand-alone fan replacement: If the fan is a separate unit (some designs), lift it free after disconnecting and removing its screws. Transfer thermal pads if they were between fan shroud and memory chips.
Heatsink Removal
  1. 1
    Identify heatsink screw order: Heatsink screws are usually numbered or follow a specific tightening/loosening order. Loosen in the reverse of the numbered order (e.g. if numbered 1–4, loosen 4→3→2→1). This releases pressure evenly across the die surface and prevents cracking.
  2. 2
    Note thermal pad locations: Before removing, photograph the heatsink from above. Thermal pads cover VRAM chips, VRM components, and other ICs. Note their positions, sizes, and approximate thickness (common: 0.5mm, 1mm, 1.5mm, 2mm).
  3. 3
    Break the thermal paste bond: After all screws are removed, grip the heatsink assembly gently and rotate it slightly (5–10°) to break the adhesion of dried thermal paste. Never pull straight up — the paste bond can be significant and you risk lifting the die or damaging substrate.
  4. 4
    Lift heatsink assembly free: Once the paste bond is broken, lift the assembly clear. Set it component-side down on a clean surface.
  5. 5
    Clean old thermal paste: Apply a small amount of 90%+ isopropyl alcohol to a lint-free cloth or coffee filter. Gently wipe the CPU/GPU die surface and the heatsink contact plate in straight strokes until no paste remains. Do not use cotton balls (leave fibers).
  6. 6
    Replace thermal pads: If thermal pads are dried/cracked, replace them with new pads of the correct thickness. Match the original thickness — pads that are too thin won't make contact; too thick compress excessively. Cut to size if needed.
  7. 7
    Apply new thermal compound: Place a small pea-sized (2–3mm diameter) dot of thermal compound in the center of the CPU die. For larger dies (some gaming laptop APUs), use a thin cross pattern instead. Heatsink pressure will spread it.
  8. 8
    Reinstall heatsink: Lower heatsink onto CPU die. Tighten screws in the numbered order (1→2→3→4) with light progressive torque — finger tight first across all screws, then tighten fully in sequence. This ensures even pressure across the die.

  • What it is: A dedicated microcontroller (BMC — Baseboard Management Controller) on the server motherboard with its own network interface, separate from the main OS.

Diagnostic Indicators
Q-LED / Debug LEDs
  • Found on ASUS ROG/TUF, MSI, Gigabyte Aorus boards
  • 4 LEDs labeled: CPU, DRAM, VGA, BOOT
  • The LED that stays lit indicates where POST failed
  • CPU LED on: CPU not seated, no CPU power (EPS cable), incompatible CPU (BIOS update needed)
  • DRAM LED on: RAM not fully seated, incompatible RAM, wrong slots populated
  • VGA LED on: GPU not seated, PCIe power not connected, monitor cable issue
  • BOOT LED on: No bootable storage found, incorrect boot order, corrupted bootloader
POST Beep Codes
  • Beep codes require a case speaker (not motherboard buzzer — they're different)
  • Beep patterns differ between BIOS vendors (AMI, Award/Phoenix, InsydeH2O)
  • AMI common codes: 1 short = OK (on some boards); 3 short = RAM error; 5 short = CPU error; 8 short = display card error
  • Award/Phoenix: 1 long + 2 short = display card error; continuous long beeps = RAM not detected
  • Refer to motherboard manual for exact codes — they vary by board
  • No speaker installed = silent failure; always connect case speaker for diagnostics

  • Small 7-segment LED display on high-end motherboards (ASUS ROG Maximus, MSI MEG)
  • Displays 2-digit hexadecimal codes as POST progresses
  • A stopped code indicates where POST halted
  • Common codes (AMI BIOS): 00 = Not used; 05 = Early CPU init; 13 = Early memory init; A0 = IDE init; A8 = BIOS setup; 00/FF after completion = successful POST
  • Full table of codes in motherboard manual appendix
The Breadboard Test — Primary Diagnostic Method
  1. 1
    Minimum hardware configuration: Remove the motherboard from the case. Place it on a non-conductive surface (its own anti-static bag or a cardboard box). This eliminates case-related short circuits from misaligned standoffs.
  2. 2
    Minimum components: Install only CPU + 1 RAM stick (in the recommended primary slot, usually A2 or DIMM1) + CPU cooler + PSU. Connect 24-pin + 4+8 CPU power. Connect monitor to onboard video (if available) or GPU.
  3. 3
    Short the power pins: Use a flat-head screwdriver to momentarily bridge the PWR_SW header pins (or connect the power button). The system should attempt to POST.
  4. 4
    Observe result: Fan spins + display = CPU and RAM are working. Add components one at a time: second RAM stick → GPU → storage → add-in cards. Remove components until the issue is isolated.

Pipelining is a hardware implementation technique in which multiple instructions are overlapped in execution. Throughput Calculation
Ideal Pipeline Speedup

If executing N instructions with a k-stage pipeline, ideally the pipeline delivers 1 instruction result per clock cycle (after filling). For a single instruction, time = k cycles. For N >> k instructions, throughput ≈ 1 instruction/cycle = CPI (Cycles Per Instruction) of 1.

Speedup vs non-pipelined = k (stages). A 5-stage pipeline ideally runs 5× faster than non-pipelined. Real speedup is limited by pipeline hazards.

Pipeline Hazards — Complete Coverage
1. Structural Hazards
  • Definition: Two instructions in different pipeline stages require the same hardware resource simultaneously
  • Example: Single-ported memory — IF stage tries to fetch instruction from memory while MEM stage reads data from the same memory
  • Solution: Separate instruction cache (L1-I) and data cache (L1-D) — the Harvard architecture split eliminates this hazard for caches. For other shared resources: stall or duplicate hardware.
2. Data Hazards (RAW, WAR, WAW)

Data Forwarding / Bypassing Instead of waiting for WB to complete before the next instruction's ID stage, bypass paths route the computed result directly from EX or MEM stage outputs to the next instruction's EX stage inputs. This eliminates most RAW stalls. A load-use hazard (result from MEM needed immediately) still requires one stall cycle even with forwarding.
3. Control Hazards (Branch Hazards)
  • Cause: On a branch instruction, the CPU doesn't know the next PC until the branch is resolved (EX or later stage). Meanwhile, the pipeline has already fetched the next sequential instructions.
  • Branch penalty: If the branch is taken, the speculatively-fetched instructions must be flushed (converted to NOPs/bubbles). Penalty = number of stages between IF and branch resolution stage.
  • Static branch prediction: Always predict not-taken (flush if taken) or always predict taken. Simple; low accuracy (~50–70%).
  • Dynamic branch prediction: Hardware maintains a Branch History Table (BHT) with 1-bit or 2-bit saturating counters per branch PC. Accuracy: 85–95%.
  • Two-level adaptive prediction: Uses branch history register + BHT indexed by both PC and history. Correlation predictor (gshare, gselect). Accuracy: 95%+.
  • TAGE predictor: Tagged Geometric branch predictor (Intel Haswell+). Uses multiple tables with different history lengths; tournament selection. Best known predictor in CPUs today.
  • Speculative execution: CPU executes instructions beyond a branch speculatively; flushes and corrects on misprediction.
  • Branch delay slot: RISC architecture solution — execute 1 instruction after branch regardless (compiler fills with useful instruction or NOP).
Modern Superpipeline & Superscalar
Superpipelining
  • Deeper pipelines (14–20 stages in modern x86 CPUs like Skylake, Zen 4)
  • Each stage does less work → allows higher clock frequency
  • Tradeoff: branch misprediction penalty grows proportionally (15–20 cycles for modern CPUs)
  • Intel Pentium 4 Prescott: 31-stage pipeline — too deep; misprediction cost too high
Superscalar Out-of-Order (OoO)
  • Issue multiple instructions per cycle from a window of instructions (IPC > 1)
  • Instructions analyzed for dependencies; independent instructions execute simultaneously
  • Reorder Buffer (ROB) tracks in-flight instructions; commits in program order
  • Tomasulo algorithm: operand forwarding + out-of-order execution with register renaming
  • Modern Intel Raptor Lake: 6-wide decode, ~500-entry ROB
  • Modern AMD Zen 4: 4-wide decode, ~320-entry ROB
Exam Key Points 5 pipeline stages: IF → ID → EX → MEM → WB. Three hazard types: Structural (resource conflict), Data (RAW/WAR/WAW), Control (branch). Data forwarding eliminates most RAW hazards; load-use requires 1 stall cycle even with forwarding. Branch prediction accuracy directly determines CPI. Register renaming (Tomasulo) eliminates WAR and WAW hazards. Speedup = k stages (ideal case); real CPUs achieve IPC > 1 via superscalar.

GPU Thread Hierarchy
GRID — Programmer launches N blocks
The entire kernel launch. Contains all thread blocks (CTAs). Mapped to the GPU globally. Size defined at kernel launch by the programmer.
THREAD BLOCK / CTA (Cooperative Thread Array)
Up to 1024 threads that share shared memory (SMEM) and can synchronize via __syncthreads(). Assigned to one SM — all threads in a block execute on the same SM. Can have 1D, 2D, or 3D shape for convenient indexing.
WARP (NVIDIA) / WAVEFRONT (AMD)
Hardware scheduling unit. NVIDIA: 32 threads. AMD: 64 threads. All threads in a warp execute the same instruction simultaneously on different data. The warp scheduler issues one instruction per clock per warp. Multiple warps interleave on the same SM to hide memory latency.
THREAD
The finest-grained execution unit. Has its own registers, program counter, and call stack. Identified by threadIdx (within block) and blockIdx (within grid). Access: globalIdx = blockIdx.x × blockDim.x + threadIdx.x
Warp Execution Mechanics
Zero-Divergence Warp (Ideal)

All 32 threads in the warp take the same code path. The warp scheduler issues one instruction; all 32 execution units process it simultaneously on their respective data. 100% SIMT efficiency. Full throughput.

Warp Divergence (Performance Killer)

When threads in the same warp take different if/else branches, the GPU executes both paths sequentially with a predicate mask — active threads execute; masked threads are disabled (their results discarded).

// This causes warp divergence if threads have different threadIdx values
if (threadIdx.x % 2 == 0) {
    result = compute_A();  // Even threads execute; odd threads masked
} else {
    result = compute_B();  // Odd threads execute; even threads masked
}
// Total execution time = time(A) + time(B), not max(A, B)
Impact Worst case: all 32 threads take different paths → effectively serial execution at 1/32 of SIMT throughput. Avoid conditional branches keyed on threadIdx or data values within performance-critical kernels.
Warp Scheduling & Latency Hiding
Multithreaded Warp Scheduling
  • Each SM has 4 warp schedulers (modern NVIDIA GPUs)
  • Each warp scheduler can issue 1–2 instructions per clock from its assigned warps
  • When a warp stalls (waiting for memory, waiting for a previous instruction's result), the scheduler instantly switches to another warp — zero context-switch cost (all warps' registers live in the register file simultaneously)
  • Memory latency (400–800 cycles): while one warp waits for global memory, the SM executes 12–25 other warps during that time
  • Occupancy: fraction of maximum possible concurrent warps active on an SM. Higher occupancy = better latency hiding. But maximum occupancy is not always optimal — it can increase register spilling.
  • Maximum concurrent warps per SM: 64 warps (Ampere/Ada), each with 32 threads = 2048 threads per SM

Each Level — Detailed
Register File
  • Fastest GPU memory. Per-thread private storage. No explicit programmer control — compiler allocates automatically.
  • NVIDIA Ada Lovelace SM: 65,536 × 32-bit registers per SM. All active threads' registers coexist — no register save/restore on warp switch.
  • More registers per thread → fewer concurrent warps (limited register file) → lower occupancy.
  • Register spilling: When a thread uses more registers than available, the excess spills to local memory (L2/global). Local memory accesses have full global memory latency — catastrophic for performance.
  • Check register usage: compile with -–ptxas-options=-v flag in nvcc.
Shared Memory (SMEM)
  • On-chip SRAM local to each SM. Shared among all threads in the same thread block.
  • Programmer-controlled: declared with __shared__ keyword in CUDA.
  • Organized into 32 banks (32-bit words). Bank width = 4 bytes. Bank i contains addresses: i, i+32, i+64, ...
  • Bank conflicts: When multiple threads in the same warp access different addresses that map to the same bank → the accesses serialize. K-way conflict = K cycles instead of 1.
  • No bank conflict: All threads access the same address (broadcast) or all threads access different banks.
  • Configurable split with L1 cache (on Ampere/Ada): 32 KB shared + 32 KB L1, or 64 KB + 0, or 100 KB shared + 28 KB L1 (varies by GPU).
  • Use case: matrix multiplication tiling, scan algorithms, reduction trees — any pattern where data loaded from global is reused multiple times within a block.
L2 Cache
  • Shared across all SMs. 32–80 MB in modern GPUs (Ada L4090: 72 MB L2 — the largest).
  • Hardware-managed; programmer cannot explicitly control what resides in L2.
  • CUDA Persistent L2 caching (Ampere+): cudaStreamSetAttribute can pin a data region in L2 for repeated access — useful for embedding tables or small model weights accessed every kernel.
  • Caches: global memory reads, constant memory, texture memory, local memory (spilled registers).

Memory Coalescing — Critical for Global Memory Performance
Coalesced vs Uncoalesced Access

Global memory is accessed in 128-byte transactions. When 32 threads in a warp access 32 consecutive 4-byte floats starting at a 128-byte-aligned address, all data is served in a single 128-byte transaction — fully coalesced.

// Coalesced: thread i accesses array[i] — all consecutive
float val = array[threadIdx.x + blockIdx.x * blockDim.x];

// Uncoalesced (strided): thread i accesses array[i * stride] — scattered
float val = array[(threadIdx.x + blockIdx.x * blockDim.x) * stride];

Strided access with stride=32 means each thread accesses a different 128-byte cache line → 32 separate transactions instead of 1. 32× more memory transactions = 32× worse bandwidth utilization.

Exam Key Points Hierarchy (fast→slow): Registers → Shared Memory → L1 → L2 → Global Memory → Host Memory. Shared memory = per-block, programmer-controlled, ~4 cycle latency. Global memory = 400–800 cycle latency; latency hidden by warp switching. Memory coalescing: 32 consecutive threads accessing contiguous aligned data → single 128-byte transaction. Bank conflicts in shared memory: multiple threads hitting same bank → serialization. Register spilling to local memory (mapped in global) = major performance hazard.

Tiling with Shared Memory — The Key Pattern
Matrix Multiplication Tiling Example

Naïve matrix multiply: each thread computes one output element, loading K elements from A and K from B from global memory → each load is O(N²×K) global memory transactions.

Tiled implementation with shared memory: load a TILE_SIZE × TILE_SIZE block of A and B into shared memory once, then compute all partial sums using shared memory → reduces global memory transactions by TILE_SIZE times.

__shared__ float As[TILE][TILE], Bs[TILE][TILE];

// Phase 1: Cooperatively load tile from global into shared
As[ty][tx] = A[row * N + (ph * TILE + tx)];
Bs[ty][tx] = B[(ph * TILE + ty) * N + col];
__syncthreads();  // Barrier: all threads must finish loading

// Phase 2: Compute dot product using shared memory
for (int k = 0; k < TILE; k++) {
    Cval += As[ty][k] * Bs[k][tx];  // Fast SMEM access
}
__syncthreads();  // Barrier before loading next tile
Bank Conflicts — Analysis & Avoidance
Shared Memory Bank Structure
  • Shared memory divided into 32 banks. Bank width = 4 bytes (32-bit) in most configurations.
  • Address-to-bank mapping: bank index = (address / 4) % 32
  • No conflict: All 32 threads access different banks (any permutation)
  • No conflict (broadcast): All 32 threads access the same address (hardware broadcasts)
  • 2-way conflict: 2 threads access different addresses in same bank → 2 serial transactions
  • 32-way conflict (worst case): All threads access the same bank → fully serial

Common conflict scenario — row-major 2D shared array accessed column-wise:

// s[TILE][TILE] — accessing column j by thread tx:
float val = s[tx][j];  // s[0][j], s[1][j], ... s[31][j]
// All addresses differ by TILE floats = TILE*4 bytes
// If TILE=32: address spacing = 128 bytes = 32 banks apart → same bank!
// FIX: declare s[TILE][TILE+1] — padding breaks the bank alignment

Architectural Power Efficiency Techniques
1. Reduced Numerical Precision
  • Energy per floating-point multiply scales roughly with the square of the bit width: halving precision → ~4× less energy per operation
  • FP32 → FP16: ~4× more ops per watt on same silicon area. FP16 → FP8: another ~4×. FP8 → FP4: another ~4×.
  • Modern LLMs can be quantized to FP8 (inference) or FP4 (aggressive quantization) with acceptable accuracy loss
  • Accumulation is still done in FP32 to prevent numerical catastrophe — the mixed-precision approach
  • NVIDIA Transformer Engine: selects precision automatically, maximizing throughput while monitoring numerical metrics
2. Structured Sparsity (2:4 Sparsity)
  • Introduced in NVIDIA Ampere. Enforces a specific sparsity pattern: for every 4 consecutive weights, exactly 2 must be zero.
  • This 2:4 pattern allows a hardware-accelerated sparse matrix multiply that skips zero computations → 2× throughput for sparse matrices at no accuracy cost (with fine-tuning).
  • The sparse weights are stored in compressed format: values (50% of original) + 2-bit metadata indicating which 2 of 4 weights are non-zero.
  • Requires a pruning phase during training to impose the 2:4 structure, followed by fine-tuning to recover accuracy.
  • Result: 2× performance gain for Tensor Core operations on networks trained with 2:4 sparsity.
3. Dynamic Voltage-Frequency Scaling (DVFS)
  • GPU clocks are not fixed. DVFS dynamically adjusts operating frequency and supply voltage based on workload and temperature.
  • Power ∝ C × V² × f (capacitance × voltage² × frequency). Reducing both V and f simultaneously reduces power cubically.
  • Base clock vs Boost clock: GPUs operate at lower base clock under sustained load (power/thermal limits) and boost for short bursts
  • Power limit (TDP): the operating frequency drops if instantaneous power exceeds the configured TDP
  • Clock gating: idle SMs, memory controllers, and logic blocks are clock-gated (their clock signal disabled) → zero dynamic power. NVIDIA calls this "fine-grained power gating."
  • Temperature-aware throttling: GPU reduces clock when junction temperature approaches T_max (typically 83–90°C for GPU junction)
4. HBM vs GDDR — Memory Power Efficiency
  • Data movement is the dominant power consumer in modern AI workloads — often 50–80% of total GPU power
  • HBM3e achieves ~3–5× better bandwidth-per-watt than GDDR6X at equivalent bandwidth
  • Short physical interconnect (interposer, microbumps) between GPU die and HBM stack → lower signal swing, lower I/O power
  • Near-memory computing (in-memory processing): future architecture trend to place compute logic inside HBM stack to minimize data movement
  • CoWoS (Chip-on-Wafer-on-Substrate) packaging enables HBM stacks next to GPU die — shorter traces = less energy
5. NVLink vs PCIe Power Efficiency
  • PCIe 5.0 x16: 128 GB/s peak at ~30W for the link itself
  • NVLink 5.0: 1.8 TB/s at similar or lower energy-per-bit — 10–15× more bandwidth per watt than PCIe for GPU-GPU transfers
  • Reducing inter-GPU communication energy significantly improves system power efficiency in multi-GPU clusters
  • NVLink-C2C (Chip-to-Chip): used within the GB200 dual-die package at 900 GB/s with extremely low energy — orders of magnitude more efficient than any PCIe or NVLink between separate chips
Liquid Cooling for High-TDP GPUs
Cooling Technologies
  • Air cooling: Effective up to ~400W per GPU. Blower cooler (rear exhaust) or open-air (3-fan). High noise levels at sustained load.
  • Direct liquid cooling (DLC): Coldplate directly on GPU die. Liquid (water-glycol) carries heat to rack-level heat exchanger. GB200 NVL72 uses DLC — enables 1000W per GPU in dense rack.
  • Immersion cooling: GPU cards submerged in dielectric fluid. 2-phase immersion (fluid boils at chip surface, condenses at top) can handle any TDP. Experimental/specialized data centers.
  • Thermal runaway prevention: If cooling fails, GPU reduces clock (thermal throttling) → eventually shuts down via hardware protection before damage.
Exam Key Points Power ∝ V² × f — reducing voltage and frequency reduces power cubically. Structured 2:4 sparsity: exactly 2 of every 4 weights are zero → 2× Tensor Core throughput with hardware acceleration. DVFS: dynamically scales voltage and frequency — more efficient at lower utilization. Clock gating: disables clock to idle units → zero dynamic power. HBM3e: 3–5× better bandwidth/watt vs GDDR6X. Data movement (DRAM reads) dominates AI workload power — minimizing transfers is key.

PTX vs SASS — Key Distinction
  • PTX (Parallel Thread Execution): Architecture-independent virtual ISA. Human-readable assembly-like IR. Forward-compatible: PTX compiled for sm_80 can be JIT-compiled by driver to run on sm_90 GPUs.
  • SASS (Streaming ASSembler): Architecture-specific native ISA. Not documented by NVIDIA but reverse-engineered by researchers. Maximum performance — no JIT overhead.
  • Fatbinary: CUDA executable can embed multiple PTX versions + multiple SASS versions for different GPU architectures (–gencode flags).
  • JIT compilation: If no native SASS matches the GPU, the CUDA driver JIT-compiles the embedded PTX at first run. Cached in user's compilation cache.
Key NVCC Optimization Techniques
Loop Unrolling
  • Replicates the loop body N times, reducing loop overhead (branch, counter update) and exposing more independent instructions for the warp scheduler
  • Allows the compiler to schedule independent instructions across unrolled iterations, increasing instruction-level parallelism (ILP)
#pragma unroll 4
for (int k = 0; k < K; k++) {
    result += A[k] * B[k];  // Unrolled 4× by compiler
}
  • #pragma unroll N: unroll exactly N times (partial unroll for loops longer than N)
  • #pragma unroll: fully unroll (only if trip count is constant and small)
  • Over-unrolling increases register pressure → may reduce occupancy
Function Inlining
  • __forceinline__ __device__: forces compiler to inline a device function. Eliminates function call overhead (register saves, branch, return).
  • __noinline__: prevents inlining — useful when a function is called many times and binary size matters
  • Device functions are inlined by default in CUDA unless the compiler decides against it. __forceinline__ overrides this decision.
  • Inlining exposes more optimization opportunities across the call boundary (constant propagation, common subexpression elimination)
FMA — Fused Multiply-Add
  • The compiler automatically combines separate multiply + add into a single FMA instruction: result = a * b + c → single hardware instruction
  • FMA executes in 1 cycle vs 2 cycles for separate mul + add. Also preserves more floating-point precision (only 1 rounding step vs 2).
  • CUDA Fast Math mode (-use_fast_math): uses hardware intrinsics that sacrifice IEEE 754 compliance for speed (sin, exp, rcp, rsqrt become fast approximations). Up to 2–4× faster for math-heavy kernels. Use only if accuracy loss is acceptable.
Memory Access Optimizations
  • __restrict__ keyword: Tells compiler that two pointer arguments don't alias (point to overlapping memory). Without this, the compiler must assume any write through one pointer might affect another pointer's data → prevents load hoisting and many optimizations. With __restrict__, compiler can freely reorder loads/stores and cache values in registers.
  • Asynchronous copy (cp.async / cuda::memcpy_async): Ampere+ hardware can copy from global to shared memory asynchronously, overlapping with computation. No warp stall during the copy. Critical for software pipelining.
  • Software pipelining: Overlap data load for iteration N+1 with computation for iteration N. Requires cp.async + pipeline barrier objects (cuda::pipeline). Effectively hides global memory latency for iterative kernels.
  • Vectorized loads (float4, int4): Loading 128 bits in a single instruction (4 floats) vs 4 separate 32-bit loads. More efficient use of memory bandwidth. float4 val = *reinterpret_cast<float4*>(&arr[idx])
Occupancy Optimization
  • Occupancy = active warps per SM / maximum warps per SM. Higher occupancy ≠ always better performance, but very low occupancy (<25%) typically hurts performance.
  • Limiting factors: register count per thread, shared memory per block, block size (threads per block).
  • CUDA Occupancy Calculator: cudaOccupancyMaxPotentialBlockSize() API finds block size that maximizes occupancy given the kernel's resource usage.
  • Launch bounds: __launch_bounds__(maxThreadsPerBlock, minBlocksPerSM) hints to compiler to stay within register budget for target occupancy.
  • Shared memory configuration: Use cudaFuncSetAttribute(kernel, cudaFuncAttributePreferredSharedMemoryCarveout, 75) to request 75% of available configurable shared memory.

Why GPUs Dominate Deep Learning
The Arithmetic Intensity Argument

Deep learning is fundamentally matrix multiplication: Y = XW + b. A single linear layer with batch size B, input dim N, output dim M requires 2×B×N×M FLOPs to compute, but only reads B×N + N×M + B×M elements from memory. For large matrices, this ratio (FLOPs / bytes accessed) — the arithmetic intensity — is very high.

The Roofline Model
Roofline Model Explanation

The roofline model predicts the achievable performance of a kernel based on two hardware limits:

  • Memory bandwidth roof: Performance = Arithmetic Intensity × Memory Bandwidth. If the kernel reads/writes large amounts of data relative to compute, memory bandwidth limits it.
  • Compute roof: Performance = Peak FLOPS. If the kernel does many FLOPs per byte accessed (high arithmetic intensity), it is compute-bound.
  • Ridge point: The crossover arithmetic intensity where a kernel transitions from memory-bound to compute-bound. = Peak FLOPS / Peak Bandwidth.
  • Example H100: Ridge = 3958 TFLOPS / 3.35 TB/s ≈ 1180 FLOPS/byte. Large transformer attention (well-optimized) often sits at or above the ridge point.
  • Action: For memory-bound kernels, optimize for coalesced access and cache reuse. For compute-bound kernels, maximize Tensor Core utilization and minimize warp stalls.

Distributed Training Architectures
Data Parallelism
  • Each GPU holds a full model copy. Mini-batch is split across GPUs.
  • Each GPU computes forward + backward pass on its shard of the batch.
  • Gradients are synchronized via AllReduce (averaged across all GPUs) before optimizer step.
  • NCCL (NVIDIA Collective Communications Library) manages the AllReduce over NVLink or InfiniBand.
  • Scales well for small-medium models that fit in one GPU's memory.
Model Parallelism / Pipeline Parallelism
  • Tensor Parallelism: Split weight matrices across GPUs. Each GPU computes a shard of the matmul. Requires AllReduce after each layer.
  • Pipeline Parallelism: Different layers assigned to different GPUs. Micro-batches flow through the pipeline stage by stage. GPUs do not wait idle (pipelined scheduling).
  • 3D Parallelism (DeepSpeed / Megatron-LM): Combines data + tensor + pipeline parallelism. Used to train GPT-4 scale models (100B+ params) across thousands of GPUs.
  • CPU role: orchestration, optimizer state management (ZeRO-Offload moves optimizer state to CPU RAM)

CPU Role in GPU-Accelerated AI Systems
CPU is Still Critical — It Does Not Disappear
  • Dataloader and preprocessing: PyTorch DataLoader uses multiple CPU workers (num_workers=8+) to load, decode, and augment data to keep GPUs fed. Slow CPU preprocessing = GPU idle = wasted throughput.
  • Model orchestration: The Python training loop, loss computation, optimizer calls, LR scheduler — all on CPU. Well-optimized; not a bottleneck for most workloads.
  • ZeRO-Offload (DeepSpeed): Moves optimizer state (momentum, variance) to CPU RAM to train models larger than GPU VRAM. CPU performs optimizer step while GPU does forward/backward.
  • Sampling / decode in LLM inference: Autoregressive token sampling logic (top-p, top-k sampling) runs on CPU between GPU decode steps — though cuRand can do this on GPU too.
  • Post-processing: Detokenization, output parsing, serving logic — CPU handles request routing, batching, and serving infrastructure.
Exam Key Points GPU dominates: large matmuls (training), large batch inference, multi-GPU allreduce. CPU preferred: data preprocessing, single-sample inference, simulation environments, tree-based models, symbolic AI.
